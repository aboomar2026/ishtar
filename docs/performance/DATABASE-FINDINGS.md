# Database findings

Runtime uses Prisma 6.19 over PostgreSQL (Supabase hosting); no Supabase JS query layer is present in the inspected route graph. The Prisma singleton is reused within its module/runtime. Production engines include native and rhel-openssl-3.0.x for Netlify. Actual Supabase/function regions, pooler endpoint, connection limits, production latency, retries/exhaustion and live query plans are **not verified**. Do not infer a region from this loopback experiment.

Confirmed reductions: collection metadata no longer hydrates 24 unused products; product pills no longer calculate covers/counts; request-scoped session checks deduplicate page/layout guards; admin products hydrate 24 rows after filtering and ordering instead of every relation. Admin stock semantics are unchanged: sum nonnegative quantities of active variants, minimum threshold of active variants, inactive variants still included in variantCount. Search wildcards are escaped and SQL values are parameterized; sort SQL is selected from code constants. Stable ID ties prevent duplicate/omitted rows across pages when the dataset is unchanged. Changing data between page requests can still shift offset pagination.

Catalog newest/price ordering formerly attached the sales aggregate to every candidate before pagination. The new MATERIALIZED page computes display sales for at most 48 selected IDs; best-seller ordering still uses real non-canceled order sums before limiting. Imported Product.soldCount is not substituted for authoritative ranking. Query count need not fall here; the operation bounds are the optimization. Live-scale time/EXPLAIN gains are not claimed. A 100-product semantic test spans all pages and sort modes with pending/delivered/canceled synthetic orders.

Existing schema indexes include category/product/collection slugs, ProductImage product references, ProductVariant product/activity, OrderItem product/order/variant, Order status/date and collection membership keys. No new index was justified by a production plan, so **no schema/index migration or live SQL change** is included. SQL fixtures only run inside newly created local test databases. Inspect EXPLAIN (ANALYZE, BUFFERS) on an authorized replica before adding composite/trigram indexes; do not multiply write overhead speculatively.

Remaining: full detail-shaped product rows/variants/images in card responses; unbounded inventory and collection editor lists; multiple dashboard counts and notification reads. Homepage still has multiple independent catalog groups (already parallel). No broad dashboard/order cache added. Local statement counts and execution medians are in BENCHMARKS.md; they exclude remote network and provider cold starts.

Order mutation code was not changed. Isolated checkout tests verify current server price, idempotent recovery, rollback and stock deductions with mocked Telegram. Conventional independent-backend last-item races require ISHTAR_TEST_POSTGRES_URL and were not run here: neither PostgreSQL nor Docker is installed. PGlite must not be presented as proof of independent concurrent transactions.
