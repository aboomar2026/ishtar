# Remaining production acceptance

The existing Netlify/Supabase/Cloudinary stack remains technically suitable for an MVP and this patch adds no paid dependency. **Measured capacity and quota feasibility are not established.** Evidence is limited to 100 products, seven sequential warm HTTP samples per route and a local database; it cannot establish users/day, concurrent checkout capacity, monthly bandwidth/transform/function usage or a safe live traffic ceiling.

Before claiming real-user targets, run desktop/mobile production-like Chromium traces on an authorized preview with representative sanitized data: Home→Product/Collection, Collection→Product, Product→Related/Cart, Search→Product, Cart→Checkout and Admin→Orders/Products/Collections. Compare first/repeated navigations with the same CPU/network settings; measure actual product/image visibility, LCP/CLS/TBT, request type bytes and cache behavior. Use real field data for p75 INP/LCP claims. Browser download was blocked here; mobile/keyboard/screen-reader/visual acceptance is still required, especially responsive images, next/form query clearing.

Verify the Netlify adapter's persistent Data Cache/tag invalidation on preview after an admin hero save; local Next production behavior is tested, adapter behavior is not. Review actual account usage and remaining credits, Supabase/function regions, pooled DATABASE_URL and reasonable per-function connection limits without revealing credentials. Capture image response Cache-Control and cold/warm transform costs. The adapter package is configured but not pinned in this repository. Avoid unnecessary extra preview builds; no hosting/domain migration is included.

Profile unbounded inventory/collection editors and repeated dashboard aggregates next; preserve edit state and server authorization while paginating. Consider slimming card DTOs and streaming secondary PDP content only after browser tests can verify no shifts/flash and SEO remains server rendered. Consider persistent public catalog caching only with tested invalidation for all product/category/collection/order/stock mutations, including metadata/sitemap visibility.

Known baseline test failures: the commerce mock mishandled tagged Prisma templates (fixed in this patch's test harness); dashboard analytics fixture assertions fail on this runtime even with original catalog source. Investigate Node/ICU versus PostgreSQL timezone-data alignment and run the existing Node-22 CI checks before accepting analytics. One collection seed test process failed under the large parallel test batch, then passed alone. No analytics behavior was silently changed to force a green run. Segment loading candidates were removed after the HTTP SEO suite caught soft-404 responses from early streaming.

Run conventional PostgreSQL race tests in existing CI (already provisions a dedicated DB). No stress/load testing of the free shared production stack was attempted. Keep PR #3 open; no merge, production deploy, Vercel migration, live order or live Telegram test was performed deliberately.
