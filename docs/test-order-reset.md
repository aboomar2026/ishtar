# تصفير طلبات الاختبار وإضافة منتجات تجريبية

التنفيذ مدمج مع فرع PR #3 في مستودع `aboomar2026/ishtar`، مع الحفاظ على صلاحيات الطلبات والترقيم والتنبيهات الحالية، وليس نسخة `src.zip` القديمة. لا يتطلب تعديل schema أو migration.

## تفعيل زر التصفير

1. انشر تغييرات الكود أولاً.
2. في Netlify أضف `ENABLE_TEST_ORDER_RESET=true` إلى متغيرات البيئة، بنطاق Builds وFunctions، ولبيئة الاختبار المقصودة فقط، ثم أعد النشر.
3. ادخل بحساب دوره `SUPER_ADMIN`، وافتح `/admin/orders`.
4. اضغط «تصفير طلبات الاختبار»، راجع ملخص جميع الطلبات بغض النظر عن الفلاتر، واكتب `تصفير الطلبات` ثم أكد.

**التصفير حذف نهائي لجميع حالات الطلبات، بما فيها المسلّمة.** يعيد كميات الطلبات غير الملغاة فقط؛ الملغاة أعادت كمياتها سابقاً. هذا يعكس الكميات المخصومة لهذه الطلبات، وليس استعادة نسخة تاريخية من المخزون. تعديلات المخزون اليدوية تبقى محفوظة.

المنتجات والصور والخيارات والتصنيفات والعملاء تبقى. تنخفض `soldCount` بمقدار وحدات الطلبات غير الملغاة، دون النزول تحت الصفر. تبقى سجلات المخزون السابقة وتضاف حركة `RESTOCK` للاسترجاع، بينما تحذف تفاصيل الطلبات وسجل حالاتها. لا ترسل العملية رسائل Telegram جديدة، ولا تحذف الرسائل القديمة. تُحذف تنبيهات الطلبات المحذوفة ومحاولاتها وحالة قراءتها إذا كانت جداول التنبيهات مثبتة؛ وإذا كان تنبيه قيد الإرسال تُرفض العملية حتى ينتهي.

العملية داخل transaction واحدة؛ أي فشل يعيد جميع التغييرات. يُرفض التنفيذ إذا تغيرت الطلبات بين الملخص والتأكيد أو وجد خيار محذوف يتعذر إرجاع كميته. الطلبات الجديدة بعد أخذ لقطة التنفيذ تبقى. لا تشغّل اختبارات طلبات أخرى بالتزامن إن أمكن. بعد الحذف قد تبدأ أرقام طلبات اليوم من البداية لأن الترقيم الحالي يعتمد على عدد الطلبات.

**قبل استقبال طلبات حقيقية:** أعد المتغير إلى `false` أو احذفه، وأعد النشر. الزر لا يعرف تلقائياً أي الطلبات حقيقية وأيها وهمية؛ إنه مخصص لقاعدة بيانات الاختبار.

## إضافة 100 منتج بصور

بعد نشر إعداد السماح بصور `cdn.dummyjson.com`، افتح Supabase SQL Editor في قاعدة الاختبار ونفذ محتوى:

`scripts/sql/ishtar-test-products-100.sql`

انسخ محتوى الملف كاملاً إلى تبويب SQL جديد وشغّله دون تحديد جزء منه. الإصدار الحالي يستخدم كتلة `DO` واحدة؛ إنشاء الجداول المؤقتة واستخدامها يتمان في نفس التعليمة والمعاملة. عند النجاح قد يظهر `Success. No rows returned`، ويظهر عدد المنتجات المضافة ضمن NOTICE إذا كان المحرر يعرضه.

الملف ينشئ 100 سجل منتج و100 خيار، ومعارض صور، وتصنيفات بأسماء طبيعية مناسبة للمتجر، وسجلات مخزون افتتاحية. الأسعار اصطناعية بعملة المتجر. توجد عينات متوفرة وأخرى قليلة أو نافدة لاختبار واجهات المخزون. المنتجات منشورة `ACTIVE` لذلك تظهر للمتسوقين في هذه البيئة.

المصدر: https://dummyjson.com/docs/products — لقطة 24 أكتوبر 2026. اخترنا 46 منتجاً أصلياً في المكياج والعطور والعناية بالبشرة والنظارات والملابس والحقائب والمجوهرات والأحذية والساعات. نكرر بعض المنتجات والصور للوصول إلى 100 سجل، مع الحفاظ على الاسم الطبيعي دون لاحقة مجموعة؛ ليست 100 صورة منتج مختلفة. يوجد 143 رابط صورة مختلفاً في المصدر. هذه روابط خارجية، وليست صوراً مرفوعة إلى حساب Cloudinary.

**الملف يضيف المنتجات الناقصة ويصلح النصوص القديمة التي ولّدناها فقط:** يحافظ على الأسعار والمخزون والصور وأي نص غيّرته يدويًا، ولا يعيد تعبئة المخزون عند إعادة تشغيله، ولا يكرر المنتجات. إذا حُذف خيار أو صورة لمنتج موجود، إعادة التشغيل لا تعيدهما؛ عدلهما من الأدمن.

الأسماء والأوصاف والأقسام والوسوم وتفاصيل المنتجات ورموزها والنص البديل للصور وروابطها تستخدم محتوى طبيعيًا؛ ملاحظات الاختبار والمصدر موجودة في الكود وتعليقات SQL فقط. معرّفات الصفوف الداخلية ثابتة للحفاظ على العلاقات. تكرار أسماء المنتجات مسموح؛ يميز بينها ID وSKU وslug. الإصلاح يزيل أيضًا أسماء المجموعات المولّدة سابقًا من الأسماء وتفاصيل المنتجات والنص البديل للصور.

إذا سبق تنفيذ الملف القديم وتريد تصحيح النصوص فقط دون إضافة منتجات، نفّذ `scripts/sql/ishtar-product-content-repair-100.sql`. يصلح النصوص القديمة المطابقة حرفياً، ورموز المنتجات والروابط التي ولّدناها؛ أي نص عدّلته يدويًا يبقى. الملف الكامل يحتوي الإصلاح نفسه ثم يضيف السجلات الناقصة. لن تتغيّر كميات المخزون أو الأسعار أو روابط الصور أو الطلبات.

لتوليد ملف 200 منتج من نفس مجموعة الصور:

```bash
npm run db:test-products:sql -- 200
```

هذا الأمر يولد SQL فقط ولا يتصل بقاعدة البيانات. افتح الملف الناتج `scripts/sql/ishtar-test-products-200.sql` ونفذه في Supabase. إذا سبق تنفيذ ملف 100، ستضاف المنتجات 101–200 فقط.

## التحقق المحلي

- `npm run lint` و`npm run typecheck` و`npm run build`.
- `npm run test:order-reset`: قاعدة PostgreSQL مؤقتة، حالات pending/delivered/canceled، منع الإرجاع المكرر، رفض الملخص القديم، خيار محذوف، rollback بعد تعديل المخزون، والحفاظ على المنتجات والصور وسجل المخزون.
- `npm run test:test-products`: تنفيذ SQL فعلي على PostgreSQL مؤقتة، ثم إعادة تنفيذه للتأكد من الحفاظ على البيانات والمخزون اليدوي.
- اختبارات التجارة وcheckout الحالية.
- تحقق HTTP HEAD من جميع روابط الصور الـ143: أعادت HTTP 200 وContent-Type لصورة.
- فحص Playwright محلي على 1440×1000 و390×844: ملخص كامل مع فلتر نشط، عبارة التأكيد، Escape، تنفيذ Server Action وإرجاع المخزون، وإخفاء الزر عن `CATALOG_MANAGER`، بدون أخطاء JavaScript.

لم يتم تنفيذ حذف أو إضافة بيانات على قاعدة Supabase المنشورة.
